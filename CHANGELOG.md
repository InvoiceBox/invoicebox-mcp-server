# История изменений

Что менялось между версиями `@invoicebox/mcp-server`. Формат простой: сначала то, что
меняет поведение у читателя, потом остальное. Даты — публикации в npm.

Версию в конфигурации клиента указывайте явно: у платёжного инструмента `latest` означает,
что набор инструментов может измениться между двумя запусками одного диалога.

## 0.2.1 — 11 августа 2026

Первый выпуск через сборку, а не с машины: у пакета появляется подтверждение происхождения
(provenance) — подписанная привязка к коммиту и сборке, которую можно проверить командой
`npm view @invoicebox/mcp-server dist.attestations`. Рядом с релизом выкладывается состав
зависимостей (SBOM) в форматах CycloneDX и SPDX.

Поведение сервера не менялось: в коде правились только комментарии, набор инструментов и их
области действия те же, отпечаток каталога прежний.

Исходники и тесты открыты: репозиторий `github.com/InvoiceBox/invoicebox-mcp-server`, лицензия MIT.

## 0.2.0 — 11 августа 2026

- **Права инструмента проверяются до вызова.** Не хватает области действия — приходит
  `403` с кодом `insufficient_scope` и названием нужной области в заголовке
  `WWW-Authenticate`. Клиент по этому коду сам запрашивает права; прежде отказ приходил
  ошибкой внутри протокола, и пользователь видел «что-то пошло не так».
- **Аутентификация сессии для размещённого режима.** Предъявленный токен проверяется тем,
  что сервер обменивает его на токен к API (RFC 8693): вызовы идут от имени того, кто
  открыл сессию, а не от имени сервера.
- **Метаданные защищённого ресурса** (RFC 9728) публикуются по
  `/.well-known/oauth-protected-resource`, когда сервер действительно проверяет токены.
  Список областей действия берётся из каталога инструментов.
- Значения адресов Инвойсбокс ID по умолчанию: из настроек обязательны только секреты
  клиента.
- Заголовок отказа фильтруется до ASCII: русское описание причины в заголовке роняло
  ответ в `500` вместо `401`.

## 0.1.0 — 5 августа 2026

Первая публикация. Восемь инструментов, по умолчанию только чтение; записи включает
`INVOICEBOX_TOOLSETS=write`, возвраты — `refund`. Каждая денежная операция — в два шага с
подтверждением человеком. Транспорты: stdio и Streamable HTTP. Суточные потолки,
ограничитель частоты, защита от дублей по ключу операции, журнал без токенов.
